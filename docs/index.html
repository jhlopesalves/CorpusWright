A local-first corpus workbench for real-world text.

CorpusWright is an alpha desktop workbench for local, reproducible text analysis: frequency lists, KWIC concordances, collocates, document spread diagnostics, and safer handling of messy UTF-8 and Windows-1252 text files.

Local-first

Corpora stay on your machine. CorpusWright is a desktop application, not a hosted corpus service.

Reproducible

Exports carry manifests, cleaning configuration, tokeniser settings, and checksums for source and processed files.

Statistically careful

Frequency views foreground document range, DP and dispersion-aware defaults alongside raw counts and optional normalised rates.

Rust-fast core

The Rust core handles extraction, cleaning, counting, search, and cached analysis paths locally.

What alpha.8 covers

CorpusWright is still alpha software, but it is no longer only a preprocessing or overview tool. The current public release covers the first pass of analysis work as well as the text foundation beneath it.

Frequency List / Corpus Overview

Inspect surface tokens, lemmas plus POS where annotation is available, and POS tags. Tables include raw frequency, document range, DP and dispersion-aware defaults, with optional normalised rates.

Concordance / KWIC alpha

Surface and phrase search produce KWIC lines with sorting by file and position, node, and left or right context positions. Hits remain connected to source preview and document spread diagnostics.

Collocates alpha

Inspect collocates around the current query with raw co-occurrence count, Near query/O11, corpus frequency/f_c, and association scores such as logDice. Collocates are lazy and cached, so ordinary search can update KWIC lines without recomputing them immediately.

Text Foundation / Encoding Recovery

Preview, export, and word counts now share canonical source decoding: strict UTF-8 first, then Windows-1252 recovery for legacy Western-European, Portuguese, and French-style text files. Decode provenance is recorded in manifests and participates in cache identity.

Alpha limits

Alpha.8 is useful for real corpus work, but several analysis workflows are deliberately still in progress.

Workflow: Concordance and Collocates are functional alpha features, not the final interaction design.

Indexing: Current analysis uses scan and cached paths. The positional index is planned work and is not included in alpha.8.

Querying: CQL, N-grams, lemma/POS KWIC, and annotation-aware Concordance are not implemented yet.

Encoding: UTF-8 and Windows-1252 recovery reduce silent replacement-character surprises, but they do not claim to detect every possible legacy encoding.

Packaging: Windows builds may still trigger the usual unsigned-app warnings.

Coming next

The near-term work is about hardening alpha.8 in real corpora and preparing the indexed architecture that will eventually replace the current scan and cache paths.
