Method

CorpusWright treats cleaning as part of analysis.

The core idea is simple: corpus preprocessing should be inspectable, repeatable, and connected to the places where researchers notice problems.

Deterministic by default

Cleaning rules should behave the same way today and tomorrow. A saved configuration should be a research object, not a vague memory of GUI clicks.

Review before removal

Repeated artefact detection is evidence, not permission. Candidates become cleaning rules only when the user accepts or promotes them.

Page-aware when possible

Headers and footers are page phenomena. CorpusWright distinguishes page-aware extraction metadata from flat-text fallback behaviour.

Analysis loop, not pipeline theatre

Cleaning, KWIC inspection, frequencies, and candidate review should form a tight loop. Researchers should not have to export/import repeatedly just to check whether a cleaning decision worked.

Design principles

  • Local-first: private corpora should not need cloud services.
  • Auditability: extraction warnings, cleaning rules, and project metadata should be inspectable.
  • Conservatism: the cleaner should avoid destructive guesses.
  • Statistical seriousness: future analysis features should respect corpus design, dispersion, document-level variation, and uncertainty.
